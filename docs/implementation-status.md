# Статус реализации MVP

## Реализовано

| Часть | Реализация |
|---|---|
| Daemon | `pi_kitty/daemon.py`: asyncio, Unix socket, singleton lock, проверка peer UID, graceful shutdown |
| Реестр | `pi_kitty/registry.py`: agent/generation/seq, lifecycle leases, TTL, проверка PID + времени старта |
| Kitty | `pi_kitty/kitty.py`: ограниченные subprocess без shell, Remote Control, актуальная топология |
| Discovery | Foreground pi в известных kitty; точное распознавание прямого entry point, dedup с расширением |
| Расширение pi | `pi-extension/index.ts`: lifecycle, heartbeat, coalescing, reconnect, `/kitty-status` |
| Названия диалогов | Session manager pi; немедленное обновление через `session_info_changed`, fallback heartbeat |
| Статусы | Цвет + текст, busy/idle/unknown, phase tools, отсутствие ложного idle по `agent_end` |
| Переключатель | `kitty/agents.py`: overlay, группы по полным рабочим папкам, поиск, управление клавиатурой |
| Focus | Перепроверка PID/панели, ожидание исчезновения overlay, явный endpoint + window ID, проверка активации |
| CLI | `list`, `list --json`, `focus`, `doctor`, `daemon run`, `service install/uninstall` |
| Автозапуск с kitty | `kitty/autostart.py`: watcher `on_load`, внешний worker и идемпотентный `daemon ensure`, встроенный Python kitty, без лишней вкладки |
| macOS service | Необязательная альтернатива: генерация и bootstrap/bootout персонального LaunchAgent; абсолютный Python, ротация логов |

Панель не отправляет команды выполнения или промпты в пользовательские агенты. Даемон и расширение не читают историю диалогов; при включении истории kitten локально читает метаданные и первое пользовательское сообщение для отображения и поиска. Переключение работает и между независимыми экземплярами kitty с пересекающимися числовыми window ID.

## Подтверждено проверками

Окружение: **macOS, kitty 0.45.0, pi 1.4.0**. CLI/daemon проверены под Python 3.13; kitten запускается под встроенным Python kitty 3.12. Нижняя граница Python 3.11 задана по используемому API, отдельная полная матрица версий пока не прогонялась.

### Автоматические тесты

- **33 Python-теста:** реестр, поколения, повторное использование PID, TTL, распознавание процессов, группировка, Unicode, санитаризация, реальные Unix sockets, framing, большие UTF-8 snapshots, focus и ожидание overlay, singleton, проверка endpoint, генерация/удаление LaunchAgent.
- Автозапуск: три одновременных вызова `ensure` возвращают один PID; дополнительный вызов не дублирует процесс.
- **Node-тест расширения:** отсутствие ресурсов в factory, имя/сессия/папка, busy/idle, параллельные tools, переименование, идентичность после reload и reconnect.
- **TypeScript strict type-check** против установленного API pi.
- Проверки LaunchAgent используют mocked `launchctl` и временный домашний каталог. Настоящий сервис пользователя не устанавливался.

### Реальный smoke test

`tests/live_smoke.py` запускает изолированные временные экземпляры kitty и настоящие pi **без запросов к модели**:

1. Два pi в разных рабочих папках и обычный shell в третьей вкладке.
2. Настоящие названия диалогов, idle-статусы и отсутствие shell в списке.
3. Настоящий curses-список внутри kitten, Enter и asynchronous `handle_result`.
4. Закрытие overlay до focus; активация выбранной вкладки и панели.
5. Escape сохраняет исходный фокус.
6. `/reload` без постоянного дубликата и смены agent ID.
7. Поиск и переход к агенту в **другом процессе kitty**, включая реальный `is_focused` системного окна.

Все перечисленные сценарии прошли. После теста временные daemon/pi/kitty закрыты. Тесты не меняют настройки пользователя.

Отдельный `tests/live_autostart.py` подтвердил автоматический старт daemon настоящим watcher при запуске нового экземпляра kitty и повторное использование процесса новой вкладкой. LaunchAgent для этого сценария не требуется.

Занятость pi при настоящем запросе к провайдеру в live-тесте не проверялась: состояния и параллельные tools проверены управляемыми lifecycle-событиями без расхода API.

## Отличия от исходного проекта

Исходный документ описывает целевую архитектуру шире первой реализации:

- **Нет push subscribe:** kitten обновляет список раз в секунду через bounded paginated snapshots. Daemon опрашивает топологию раз в 2 секунды. На один экземпляр нет отдельного фонового опроса для каждого агента; ручной announce может инициировать дополнительный refresh.
- Полный snapshot разбит на страницы по четыре агента с общей revision, чтобы не превышать 64 KiB даже с UTF-8 путями. При смене revision клиент повторяет чтение.
- Для TUI используется **curses из встроенного Python kitty**, без зависимости от внутреннего набора TUI-компонентов kittens. Нестабильные объекты `Boss` не используются для focus.
- Обычные kitty subprocess ограничены четырьмя слотами. Один сериализованный focus имеет отдельный приоритетный путь, чтобы недоступные посторонние экземпляры не занимали его очередь.
- Работают TOML-параметры `kitty.command` и `kitty.endpoints`. Интервалы, сортировка и UI пока не конфигурируются через TOML.
- MRU учитывает переходы через панель и хранится только до перезапуска daemon. Порядок групп — по пути, внутри группы — MRU при открытии, затем стабильный порядок.
- `last_outcome`, отдельный индикатор ошибки последнего запроса, сумма токенов и waiting-for-confirmation не реализованы. Не делаем выводы об этих состояниях по отсутствию вывода.
- Ошибка focus доступна в `doctor` и при следующем открытии списка; отдельного системного уведомления после закрытия overlay нет.
- `doctor` проверяет путь/соединение/известные экземпляры/число расширений/ошибки focus. Полный автоматический аудит конфигураций pi/kitty/launchd не реализован.
- Полноценный recovery grace-period после sleep и метрики производительности требуют отдельного этапа. Пропавшие heartbeat сейчас обрабатываются обычными TTL.

## Ограничения

- **Точные статусы и названия требуют расширения pi.** Без него доступен только ограниченный process discovery.
- Discovery распознаёт прямой `pi` и известные Node entry points. Произвольные обёртки, переименованные бинарники и фоновые процессы без расширения могут быть не найдены.
- Без доступного Remote Control endpoint экземпляр kitty неизвестен daemon до корректной настройки/регистрации. «Все агенты» — все зарегистрированные и обнаруженные в известных локальных экземплярах, не универсальное сканирование всей машины.
- Переход — к kitty-панели, не к внутренней tmux/screen-панели и не к конкретной suspended/background job в одном терминале.
- SSH, удалённые daemon и автоматическое управление tmux не поддерживаются.
- Pi вне kitty и headless pi не являются целями терминального переключателя.
- Разные macOS Spaces, свёрнутые окна и политики focus ОС не вошли в проверенную матрицу. Между обычными видимыми окнами focus проверен.
- Linux имеет базовые пути/Unix socket/peer UID, но LaunchAgent специфичен для macOS, а Linux live smoke пока не выполнялся.
- Компоненты доверяют локальному пользователю ОС. `socket-only` в kitty не является allowlist: любую доступную socket-команду могут отправить другие процессы того же пользователя.

## Как повторить

```bash
python3 -m unittest discover -s tests -v
node --test tests/extension.test.cjs
node scripts/check-extension-types.cjs
ruff check pi_kitty kitty tests
ruff format --check pi_kitty kitty tests

# Отдельно: создаёт временные GUI-окна, не запускает модель.
python3 tests/live_smoke.py
python3 tests/live_autostart.py
```

Node-проверкам нужен установленный npm-пакет pi, для type-check — `tsc`. `ruff` нужен только для lint/format, не для работы панели. Нестандартный путь к pi задаётся через `PI_PACKAGE_ROOT`.
