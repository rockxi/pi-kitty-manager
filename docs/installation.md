# Установка Pi Kitty Agents

## 1. Подготовка

Требования:

- macOS; проверено с kitty 0.45.0 и pi 1.4.0.
- Python 3.11 или новее для daemon и CLI.
- Установленные `kitty` и `pi`.
- Репозиторий по постоянному пути: kitten и LaunchAgent ссылаются на его файлы.

Сначала клонируйте репозиторий в постоянный каталог:

```bash
git clone https://github.com/rockxi/pi-kitty-manager.git ~/pi-kitty-manager
cd ~/pi-kitty-manager
```

Все команды ниже выполняются из корня репозитория. Установка не требует root, изменения shell rc-файлов или сторонних Python-библиотек.

Можно пользоваться `./bin/pi-kitty` без pip. Необязательная установка CLI в собственный venv:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e .
```

После этого команда доступна как `.venv/bin/pi-kitty`. Файл kitten по-прежнему находится в репозитории: pip-пакет не копирует пользовательское расширение kitty в настройки автоматически.

## 2. Daemon

### Автоматически при старте kitty — рекомендуемый режим

Добавь в `~/.config/kitty/kitty.conf`:

```conf
watcher /ABSOLUTE/PATH/pi-kitty-manager/kitty/autostart.py
```

Укажи собственный абсолютный путь, если репозиторий находится в другом месте. Watcher использует `on_load` kitty 0.45: при старте приложения запускает внешний worker, который проверяет daemon и при необходимости поднимает его в фоне. GUI-процесс kitty не ждёт сетевых запросов, отдельная вкладка не открывается. Работает и при запуске kitty из Dock/Finder: внешний Python в PATH не нужен, используется встроенный Python kitty.

Новые вкладки и дополнительные экземпляры kitty используют один daemon. Одновременные старты защищены singleton lock. При закрытии kitty daemon остаётся в фоне; автоматическая остановка последнего daemon не требуется.

Для текущего, уже открытого kitty один раз:

```bash
./bin/pi-kitty daemon ensure
```

`ensure` можно вызывать повторно: уже работающий процесс не дублируется. Для разработки по-прежнему доступен ручной foreground-запуск `./bin/pi-kitty daemon run`.

На macOS без XDG runtime сокет располагается здесь:

```text
~/Library/Caches/pi-kitty/run/daemon.sock
```

Каталог создаётся с правами `0700`, сокет — `0600`. Два daemon на одном сокете не запускаются. Нет TCP listener.

### Необязательно: запуск при входе в macOS, независимо от kitty

Для запуска вместе с kitty LaunchAgent **не нужен**. Если всё же нужен запуск сервиса сразу при входе в систему, сначала останови уже работающий daemon, затем:

```bash
./bin/pi-kitty service install
```

Устанавливается только собственный LaunchAgent:

```text
~/Library/LaunchAgents/local.pi-kitty.agents.plist
```

Он использует абсолютный путь к текущему Python и путь к исходникам. Поэтому после переноса репозитория или удаления Python/venv сервис необходимо переустановить.

Лог daemon с ротацией — до трёх файлов по 1 MiB:

```text
~/Library/Logs/pi-kitty/daemon.log
```

Проверка регистрации сервиса:

```bash
launchctl print "gui/$(id -u)/local.pi-kitty.agents"
```

LaunchAgent не наследует окружение текущей вкладки. Для уже настроенных kitty с сокетами вне runtime-каталога endpoint поступит от расширения pi или при первом открытии kitten. Также можно явно указать endpoint в TOML-конфигурации.

## 3. Расширение pi

Установи локальный пакет по абсолютному пути:

```bash
pi install "$(pwd)/pi-extension"
```

Это персональная установка для всех рабочих папок. Команда меняет пользовательскую конфигурацию pi; daemon сам этого не делает.

В каждом существующем pi выполни:

```text
/reload
```

Для проверки связи в pi доступна команда:

```text
/kitty-status
```

Имена диалогов задаются средствами pi:

```text
/name Исправление авторизации
```

Или при запуске:

```bash
pi --name "Рефакторинг API"
```

Панель отображает это имя и обновляет его после переименования. Для неназванного диалога показывает «Без названия». Заголовок вкладки не подменяет название диалога.

Без персональной установки расширение можно попробовать в одном процессе:

```bash
pi --no-extensions -e "$(pwd)/pi-extension/index.ts" --name "Тест панели"
```

Это отключает остальные автоматически загружаемые расширения только для данного запуска. Для обычной работы отключать их не нужно.

## 4. Kitty Remote Control

Если текущий kitty уже имеет доступный `KITTY_LISTEN_ON`, сначала попробуй существующую настройку:

```bash
./bin/pi-kitty doctor
```

Если `doctor` показывает доступный экземпляр kitty, для него достаточно установки pi-extension и hotkey; менять `listen_on` ради панели необязательно.

Для новой настройки на macOS:

```conf
allow_remote_control socket-only
listen_on unix:${HOME}/Library/Caches/pi-kitty/run/kitty-{kitty_pid}.sock
```

Каталог должен существовать **до запуска kitty**. Его создаёт `daemon run` или `service install`. Для ручной подготовки:

```bash
mkdir -p "$HOME/Library/Caches/pi-kitty/run"
chmod 700 "$HOME/Library/Caches/pi-kitty/run"
```

Изменение `listen_on` требует **перезапуска kitty**, а не только reload. Самостоятельно завершать существующие рабочие окна панель не будет.

**Важно:** `socket-only` запрещает Remote Control через TTY, но разрешает все remote-control команды через сокет. Это доверие локальным процессам с доступом к нему, а не allowlist только для переключения. Приватный каталог ограничивает доступ других пользователей, но не изолирует программы с твоим UID. Панель сама вызывает только `ls` и `focus-window`.

Даемон принимает только существующие Unix sockets своего пользователя. Не принимает TCP endpoint и не сканирует все сокеты `/tmp`. Он сканирует только свой приватный runtime-каталог; остальные endpoint передаются явно от pi/kitten или из конфигурации.

## 5. Горячая клавиша

Добавь в `~/.config/kitty/kitty.conf`:

```conf
map ctrl+shift+p kitten /ABSOLUTE/PATH/pi-kitty-manager/kitty/agents.py
watcher /ABSOLUTE/PATH/pi-kitty-manager/kitty/autostart.py
```

Для другого пути репозитория замени абсолютный путь. Его можно получить так:

```bash
printf 'map ctrl+shift+p kitten "%s/kitty/agents.py"\nwatcher "%s/kitty/autostart.py"\n' "$(pwd -P)" "$(pwd -P)"
```

При пробелах в пути заключи аргумент пути в кавычки в kitty.conf. Проверь, что это сочетание не занято. Можно выбрать другое, например `ctrl+shift+o`.

Перезагрузи конфигурацию kitty. Если менялась только привязка клавиш, перезапуск приложения не нужен.

Без горячей клавиши можно открыть список из терминала:

```bash
kitty @ kitten "$(pwd)/kitty/agents.py"
```

### Управление

- j/k, ↑/↓ или Tab/Shift+Tab — выбирать агентов, пропуская заголовки групп.
- `/` — перейти к поиску по папке, названию диалога, модели и вкладке; в режиме поиска j и k вводятся как обычные буквы.
- Esc — выйти из режима поиска; повторный Esc закрывает список.
- Backspace — удалить символ поиска.
- Ctrl+D / Ctrl+U — перейти на полэкрана вниз / вверх, пропуская заголовки папок.
- Ctrl+L — очистить поиск.
- Ctrl+T — переключать режимы: активные → активные и история → скрытые.
- dd на закрытой сессии — сразу скрыть; в режиме скрытых — вернуть.
- V на закрытой сессии, затем j/k — выделить диапазон; d сразу скрывает или возвращает выделенные закрытые чаты. Активные чаты исключены. Esc отменяет выделение.
- u — отменить последнее скрытие или восстановление (включая групповое). Доступны до 100 отмен за одно открытие панели; в режиме поиска u вводится как обычная буква.
- Ctrl+R — запросить обновление списка.
- Enter — закрыть список и перейти к выбранной панели.
- Escape вне поиска или Ctrl+C — закрыть без перехода и без отправки ввода в pi.

Группы — полные рабочие пути. Внутри группы порядок фиксируется на время открытого списка; при следующем открытии учитываются недавние переходы. Статусы обновляются на месте, выделенная строка не прыгает из-за изменения состояния соседей.

Скрытие не удаляет и не изменяет файлы pi: перечень скрытых путей сохраняется в `${XDG_CONFIG_HOME:-~/.config}/pi-kitty/hidden-sessions.json`. Если сессию перенести в другой путь, она будет считаться другой записью.

История считывается при её включении и обновляется не чаще одного раза в 10 секунд. Enter на закрытой сессии открывает новую вкладку в её рабочей папке с `pi --session <путь>`. Если сессия уже открыта и её местоположение подтверждено, выполняется переход к агенту. Для этого в уже запущенных pi после обновления расширения выполните `/reload`. Историю без указанного `/name` панель обозначает первым сообщением.

По умолчанию читается каталог сессий pi из `PI_CODING_AGENT_DIR` (или `~/.pi/agent/sessions`), а также `PI_CODING_AGENT_SESSION_DIR`, если переменная доступна kitty. Дополнительные каталоги можно задать в `PI_KITTY_SESSION_DIRS` через `:`. Для GUI-запуска kitty соответствующие переменные должны быть заданы в окружении kitty. Сессии с `--no-session` не сохраняются. Индексирование истории читает первые сообщения локально для подписей и поиска; никаких данных не отправляется модели.

## 6. Конфигурация daemon

Необязательный файл:

```text
${XDG_CONFIG_HOME:-~/.config}/pi-kitty/config.toml
```

Поддерживаемые сейчас параметры:

```toml
# Язык панели и CLI: ru (по умолчанию) или en.
language = "ru"

[kitty]
command = "/opt/homebrew/bin/kitty"
# Обычно можно оставить пустым: endpoint приходит от расширения/kitten.
endpoints = []
```

Параметр `language` должен находиться перед секцией `[kitty]`. Переменная `PI_KITTY_LANG` имеет приоритет над файлом; для панели она должна быть задана в окружении процесса kitty. После изменения языка откройте панель заново.

Можно добавить конкретный существующий endpoint:

```toml
[kitty]
endpoints = ["unix:/tmp/kitty-12345"]
```

PID/имя сокета после перезапуска kitty изменится; для постоянной работы предпочтительны регистрация расширения или сокеты в приватном runtime-каталоге.

Для разового запуска:

```bash
./bin/pi-kitty daemon run --kitty-command /opt/homebrew/bin/kitty --endpoint unix:/path/to/socket
```

Изменения TOML вступают в силу после перезапуска daemon. Параметры интервалов и UI из исходного технического проекта пока не реализованы как настройки.

### Нестандартный сокет daemon

Python-клиенты и расширение понимают `PI_KITTY_SOCKET`. При нестандартной настройке переменная должна совпадать в daemon, pi и kitten. Для CLI также есть глобальный аргумент `--socket`:

```bash
./bin/pi-kitty --socket /absolute/private/directory/daemon.sock daemon run
./bin/pi-kitty --socket /absolute/private/directory/daemon.sock list
```

Рекомендуется оставить стандартный путь, чтобы не настраивать окружение всех компонентов вручную.

## 7. Диагностика

```bash
./bin/pi-kitty doctor
./bin/pi-kitty list
./bin/pi-kitty list --json
```

| Симптом | Что проверить |
|---|---|
| Daemon недоступен | Запущен ли `daemon run`/LaunchAgent, совпадает ли путь сокета |
| Агент виден как «Без расширения pi» | Установку pi-extension и `/reload` в этом процессе |
| «Без названия» | У диалога нет имени; задай `/name ...` |
| «Нет панели» | Remote Control, существование панели, отсутствие SSH/tmux между pi и kitty |
| Нет известных kitty | `listen_on`, перезапуск kitty, открытие kitten или регистрацию pi-extension |
| Не работает hotkey | Абсолютный путь, конфликт map, reload kitty.conf |
| После Enter список закрылся без перехода | `doctor`: последняя ошибка focus; она также появится при следующем открытии списка |
| `ALREADY_RUNNING` | Уже работает ручной daemon или LaunchAgent; не запускай оба на одном сокете |

Агент с потерянной связью помечается через 15 секунд и скрывается из обычного списка после 60 секунд. Подтверждённо завершённый процесс удаляется при ближайшей проверке ОС. Состояние «Неизвестно» у discovery-агента — честное отсутствие телеметрии, а не признак зависания.

## 8. Удаление

```bash
./bin/pi-kitty service uninstall
pi remove "$(pwd)/pi-extension"
```

Удаление сервиса не меняет конфигурацию pi/kitty. Отдельно убери строки hotkey и `watcher .../autostart.py` из kitty.conf и выполни `/reload` в оставшихся pi. Если daemon был запущен вручную, останови его через Ctrl+C.

Не удаляй общую настройку Remote Control, если её используют другие инструменты. Пользовательские диалоги, репозитории и история pi не затрагиваются.
